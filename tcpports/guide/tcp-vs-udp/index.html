TCP vs UDP

TCP and UDP are the two main ways programs send data over the internet. TCP sets up a connection, numbers the data, checks that it arrived, and resends what was lost. It is used where every byte must arrive: web pages, email, file transfers. UDP just sends packets, without a connection and without a promise of delivery. It is used where speed matters more than completeness, or where each message is small and self-contained: name lookups (DNS), time (NTP), voice and video calls, many games.

Why the registry lists both

For many ports IANA has entries for both TCP and UDP, because when the registry was young it reserved the same number for both even if only one was used. So a port listed for both does not mean the service uses both. Of the 6,125 port numbers with an entry, the registry names TCP for 5,898, UDP for 5,515 and SCTP for 88.

What it means for firewalls

A firewall rule applies to one protocol: allowing TCP 443 does not allow UDP 443. Services such as DNS use UDP for normal questions and TCP for large answers, so both must be allowed for DNS to work fully. Modern web traffic (HTTP/3) also uses UDP on port 443.
