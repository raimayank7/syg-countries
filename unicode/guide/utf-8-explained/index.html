UTF-8 explained

UTF-8 is the way almost all web pages, files and messages store Unicode text. It writes each character as between one and four bytes, using fewer bytes for the characters most used in English and more for the rest. It was designed so that the first 128 characters (ASCII) take one byte each and look exactly as in ASCII, which let the old and the new coexist.

The rule

U+0000 to U+007F1 byte0xxxxxxx
U+0080 to U+07FF2 bytes110xxxxx 10xxxxxx
U+0800 to U+FFFF3 bytes1110xxxx 10xxxxxx 10xxxxxx
U+10000 to U+10FFFF4 bytes11110xxx 10xxxxxx 10xxxxxx 10xxxxxx

The x positions are filled with the bits of the code point. The first byte tells how long the character is (its leading 1 bits count the bytes), and every following byte starts with 10, so a program that lands in the middle of a text can always find where the next character begins. That is the main reason UTF-8 won.

An English letter takes one byte. An accented Latin letter, Greek or Cyrillic letter takes two. The rupee sign and the letters of Hindi, Punjabi and most other scripts take three. Most emoji and many historic scripts take four. So a Punjabi sentence is about three times larger in UTF-8 than the same number of English letters; this is the price of the scheme and it is small in practice.

UTF-16 and UTF-32

UTF-16 uses two bytes for the first 65,536 code points and a pair of two-byte units (a surrogate pair) for the rest. JavaScript, Java and Windows use it inside, which is why in JavaScript the length of "😀" is 2. UTF-32 uses four bytes for every character: simple, but large. For files and the web, use UTF-8.

Common problems

  • Question marks or boxes: the text was converted to a set that does not have the character. Save as UTF-8.
  • Strange sequences like Ã© for é: UTF-8 text was read as an older single-byte set (Latin-1 or Windows-1252). Tell the program to read the file as UTF-8.
  • A web page that shows garbled text: add <meta charset="utf-8"> near the top of the head, and save the file as UTF-8.
  • BOM: some editors put the byte order mark U+FEFF (bytes EF BB BF) at the start of a UTF-8 file. It is allowed but unnecessary, and can upset scripts; see invisible characters.
